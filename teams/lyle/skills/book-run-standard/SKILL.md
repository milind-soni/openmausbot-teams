# Novel run standard

Current under [Book making](../../SOP-BOOK-MAKING.md), Kevin's November 16, 2026 adoption. Former Light-cycle and shelved-review instructions yield to that SOP. Existing runs keep approved sources, decisions and valid checks. Do not restart from historical OPEN flags. TFB keeps its separate full workflow and eight specialist roles.

## Bind the assignment once

Use the existing WORK-ORDER.md, not another ledger. Record job ID; book/code and exact binding; source paths, versions/hashes and range; candidate/current/landed status; protected decisions; allowed supporting facts; selected skills and load timing; permitted writes/actions; absolute outputs; required checks; actual model/effort; worker app/chat; current owner/return address; original scope/time/capacity limits; next action and finish point. Include the human authorization source for any native callback. Update only changed state.

Reader assignments receive only their permitted local copy and report brief. A fresh DRAFT receives the ready card and necessary facts/voice/continuity, not planning debate, rejected drafts or reviews. A blind blurb writer receives only its pitch card, approved examples and Kevin's brief. The coordinator's source knowledge is not transferable merely because it opens the task.

## Neutral visible tasks and deliberate native selection

Use a new visible chat, never a fork or internal helper. The generic dispatcher entry is `GLOBAL-TASK <job ID>` with the exact skill assignment, in the existing memory-disabled GLOBAL project; this is a bounded task entry, not a permanent production role. The organizer installs that neutral branch before the management default. It loads only the supplied assignment and selected method, with no role wrapper, book history, profile/memory, backlog or other task's results. Until the app's dispatcher actually supports that entry, retain the prepared brief and report the launch dependency; do not run it through the no-suffix CODEX default.

Before source access the worker checks its actual supplied context. Forbidden memory or substantive prior context stops a cold task; identifying the type is enough. Renaming or a prompt to forget cannot fix it. A new chat alone is not proof of neutrality. Scoped source permissions are instructions, not a claimed operating-system sandbox. Both apps must use their supported memory-disabled neutral launch; a document cannot change their runtime settings.

Codex native create_thread exposes model and thinking. Its current contract requires an explicit user model request before setting model; otherwise omit model to use the configured default and use the authorized effort (high for the present method-launch assignment). Never silently inherit the manager's expensive override or claim a model value that has not been observed. If the named model/effort is unavailable, report the mismatch; do not silently substitute or change global settings. Claude uses its actual native selection controls and records the observed choice. A model recommendation in an old review table is not user authorization or proof of installed availability. Art-model choice and spending stay separate.

The opener chooses deliberately for the actual job and records either the user's exact selection or configured-default selection and observed model if available. No default escalation to max/ultra or another model is implied. If the necessary capability or neutral startup is unavailable, return the concrete dependency, not a claim of autonomous operation.

## Source and Bible integration

CRAFT binds the existing plan/card contract, generative guide, after-draft checks, manuscript destination and actual source-integration owner. Brainstorm prepares the card; a fresh task writes one chapter; CRAFT reads and accepts the actual chapter; a bounded Bible task records supported effects. Reuse the planning task while its assignment remains. Another chapter uses a fresh writer; repairs stay with the current writer.

For the authorized saved-file novel route, the named source owner preserves the base and mechanically assembles the exact accepted versions into the agreed source destination. Verify order, completeness, no duplicates and unchanged prose, then record the new source identity once. Candidate acceptance and authoritative integration are distinct. Use an existing project's real source procedure when it has one; a missing authorized write/landing route holds dependent work. TFB's governed integration is not replaced by this saved-file method.

Give update-book-bible the accepted chapter/source state, actual changed facts and affected Bible owners. One writer holds each authoritative range. Update required maintained representations/checks; distinguish plans, provisional facts and current page facts. Without an authorized provisional layer, keep proposed facts in task output until the source gate clears. CRAFT accepts that result before releasing a dependent next card. Full Bible Master remains after the final assigned CLEAN and before COMPLETE.

At creative finish CRAFT provides one ordered exact source, plan/payoff disposition, accepted checks, Bible status and honest issues. A frozen candidate is not silently called current. CLEAN binds the actual source, scope and approved work order; separate CHECK receives the true before/after, candidate if different, authority and change map. CHECK compares every actual changed span, including omissions from the map. CLEAN owns acceptance and repair routing, not a duplicate self-check. BM receives the final accepted source and changed-fact references.

## Proportionate checks and repair routes

Reuse completed evidence only for its exact inputs and coverage. Assembly's all-page inspection is not repeated merely because COMPLETE receives it; independent PDF proof, hardcover comparison and platform preview remain distinct gates. Revisit only changed inputs, observed defects, missing checks or concrete conflicts.

Approved editing batches contain at most four chapters, fewer when needed for length/context. Preserve the original clock. Bad collection execution/counts/locators return to its scan task; a valid prose concern goes to CLEAN's authorized work order. Failed edits return to the same editor for one repair/recheck; CHECK reports any remaining failure for restoration or Kevin's necessary decision. Do not restart successful work or silently expand scope. Layout/art defects return to their maker; source changes use the authorized editorial owner.

## Production and specialist handoffs

COMPLETE accepts CLEAN/CHECK and BM's actual source disposition before assembly. No initial manuscript proof is required. Assembly returns exact assets/hashes, source parity and actual page/device checks; each stable binding's count/specifications go promptly to design. Finished-PDF proof follows the final layout/fix round, with the assigned reader count and exact PDF identity. Source corrections require a new authorized source and affected rebuild/checks. Local QA, PDF proof, Amazon preview and physical proof remain distinct.

Blurb, KDP, marketing and assembly use their canonical skills in bounded visible tasks. The owner supplies book/series, inputs, destination and action limits. Blurb's split-card isolation remains mandatory; it has no initial-proof fifth candidate. KDP uses approved public copy and hash-bound assets, never inherits account approval. Marketing remains an assigned series job. These methods create no standing worker identities or automatic relay chain.

## Supported return and closure

Return an ordinary final containing the job ID, exact result path/source, checks, limits and next action. In Codex an active organizer can collect this through native wait_threads using the worker's threadId/hostId and cursor; use a bounded event wait, not repeated unchanged read_thread polls. This supported collection route needs no worker message authorization. If the organizer is idle, the final alone is not proof it resumes.

Send one native completed-result/blocker callback only when the tool is available and original human authorization covers messaging that destination. An organizer's request alone is insufficient under the native messaging contract. Carry the human authorization source in the opening; without it, return normally and name the missing callback authorization. No routine progress traffic or substitute mailbox/watcher is required.

On receipt the organizer reads the result, accepts its distinct responsibilities, updates the existing record and starts the next already-authorized ready task. On succession transfer Owner and callback address together with source states, pending tasks and original clocks. The opener first receives and accepts the result, then asks the worker to close. A non-role worker writes no closeout and self-archives only on that close request; a role first completes its required cycle. Keep a chat Kevin is actively using open. No separate worker closeout or acknowledgment file.

Documents and exposed schemas prove neither automatic wake nor end-to-end neutral creation. Before promising unattended operation, observe the actual required dispatch/return route, including idle/busy reception and succession when applicable. This methods update runs no production pilot, timer, hook, automation or settings change. Until observed, describe operation as coordinator-collected or explicitly resumed, not autonomous.
