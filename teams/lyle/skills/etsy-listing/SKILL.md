# Etsy listing

This method turns one product into a listing draft that will not need reworking after it goes up. Listings kept getting redone because the buyer's limits and the product's claims were settled late. Here they are settled first, and the copy is written from them. Shared by Claude, Codex and Grok; Grok follows the plain-text copy in its dated folder.

## Limits

- **Drafts only.** Publishing, editing a live listing, prices, shop settings, ads and customer messages each need Kevin's own yes for that action ([ROLE](C:/Users/kehar/Documents/PROJECTS/_SYSTEM/workers/PROJECTS-ETSY/ROLE.md), Limits). No sign-in or account action comes from this skill.
- **Bare minimum to list.** List with the least that is true and complete: real fields, honest photos, settled limits. Finish physical and made-to-order products to perfect after a sale. Exception: an **instant download must be complete at listing**, because the buyer gets the files at checkout (Etsy requires them at creation, [D1](C:/Users/kehar/Documents/PROJECTS/_SYSTEM/workers/PROJECTS-ETSY/knowledge/DIGITAL.md)).
- **No ad tracking or chasing.** No Etsy Ads or Offsite Ads setup, budgets or performance loops in this method.
- **Not the price owner.** Use the price the assignment, [listing rules](<C:/Users/kehar/Documents/GROK/Etsy Shop/11-07/listing-sops.md>) or [catalog](C:/Users/kehar/Documents/PROJECTS/ETSY/SHOP/catalog/INDEX.md) gives. If none is set, write "price: Kevin" and keep going.
- **No art or files.** Etsy does not draw or lay out products ([ROLE](C:/Users/kehar/Documents/PROJECTS/_SYSTEM/workers/PROJECTS-ETSY/ROLE.md), Job). It may open the real files to check them. Missing pictures or measurements go to Design under the role's coordinator route.

## Method

### 1. Pick the delivery type

| Type | What must exist at listing |
|---|---|
| Instant download | The complete buyer files, each under 20,000,000 bytes, five files at most, opened and page-checked. |
| Made-to-order digital | A finished sample to show, settled buyer limits, a stated turnaround. Production file comes after the order. |
| Printed / physical | Honest photos or allowed samples (see the role's print-photo notes), trim, binding, page count, settled limits, production partner set. The printed copy is made after an order. |

Digital listings cannot have price-changing variations ([D2](C:/Users/kehar/Documents/PROJECTS/_SYSTEM/workers/PROJECTS-ETSY/knowledge/DIGITAL.md)); a different price is a separate listing.

### 2. Settle the buyer limits (the configurator check)

A product configurator fails when an order that looks valid cannot be made. Our version: every thing the buyer can type or send gets a stated limit before the copy is written. Fill one line for each input:

| Input | Settle and state |
|---|---|
| Each name | Most letters that fit every place the name prints (cover, title page, story text) at the template's normal size. Measure it in the actual template with a long test name; never guess. If not measured yet, state a safe limit (for example 10 letters) and mark it "to measure". |
| Characters | Which work in the book's fonts: test an apostrophe (O'Neil), hyphen (Mary-Kate), space (Ana Sofia) and accents (Zoë, José, Niño). State plainly which are accepted. |
| Exactly as typed | Say it in the listing: the name is printed exactly as typed, including spelling, capitals and accents. Do not "fix" a buyer's name; ask in the order thread only if it looks like a typo. |
| Photo for a drawn likeness | One child per photo, face clear and front-facing, good light, no filters or sunglasses, recent. State it in the personalization box. |
| Photo printed as a photo | Minimum size for the print: inches x 300 pixels is good, inches x 150 is the floor (an 8 x 10 needs at least 1200 x 1500). State the minimum. |
| How many likenesses / names | Exactly what the product supports today (for example: one child's likeness, a second name only as text). |
| Not offered | Anything buyers will ask for that we do not do (extra children, pets, custom pages, rush). |
| Turnaround | Proof and delivery time we can keep, separate from shipping time. |

Each limit appears where the buyer reads it: the personalization box instructions and the description. An unsettled limit is a **Fix**, not a listing.

### 3. List the claims and their sources

Write down every promise the title, description and photos make: page count, trim size, file type and count, "printable", "editable", turnaround, what personalizes, who made it. Next to each, the file or record that proves it. A claim with no source is cut or marked "Needs Kevin". "Printable", "fillable", "editable template" and "personalized by us" are different products; check the file before using the word ([D4](C:/Users/kehar/Documents/PROJECTS/_SYSTEM/workers/PROJECTS-ETSY/knowledge/DIGITAL.md)).

### 4. Write the fields

- **Title:** up to 140 characters. Lead with the item and the buyer's search phrase, then the distinguishing detail (story name, occasion, format). Fewer than 15 words is advice, not a hard limit. No praise words, no repeats ([L1](C:/Users/kehar/Documents/PROJECTS/_SYSTEM/workers/PROJECTS-ETSY/knowledge/LISTING-SEARCH.md)).
- **Tags:** all 13, each 20 characters or fewer, counted. Multiword buyer phrases, varied: item, recipient, occasion, theme, format. Do not spend a tag repeating the category or an attribute. No trademarks.
- **Description:** first two lines say what it is and what the buyer gets, written for the search snippet. Then the story or product, what is delivered (from the claims list), the buyer limits from step 2, turnaround, and how the buyer sends details. End with the exact disclosure block from the [ROLE listing standard](C:/Users/kehar/Documents/PROJECTS/_SYSTEM/workers/PROJECTS-ETSY/ROLE.md); no separate photo-privacy or AI section. If a newer wording is in play, keep the ROLE block and flag the difference as "Needs Kevin" ([K2](C:/Users/kehar/Documents/PROJECTS/_SYSTEM/workers/PROJECTS-ETSY/knowledge/SHOP-DECISIONS.md)).
- **Personalization box:** the step 2 limits in short lines the buyer can follow, ending with "Printed exactly as typed." Fit the editor's character limit; check it in the editor rather than assume.
- **Etsy fields:** category (deepest true match), attributes filled, How it's made = I did / A finished product; digital = With an AI generator; Lulu as production partner on printed books only. Made to order set for personalized digital. Photos: finished example first, at least 2000 px, opaque JPG; physical items need a real photo unless Kevin's recorded sample permission covers it ([C4-C5](C:/Users/kehar/Documents/PROJECTS/_SYSTEM/workers/PROJECTS-ETSY/knowledge/CONTENT-IMAGES.md)).

### 5. QA gate before Kevin sees it

Run every check; each finding gets **Halt** (back to the writer), **Fix** (mechanical, fix it now and say so) or **Needs Kevin** (a decision only he makes).

1. **Brief:** matches the assignment's product, offer and delivery type.
2. **Buyer limits:** every input from step 2 has a stated limit in both the box and the description. "Exactly as typed" is present.
3. **Claims:** every claim has a source; nothing promises more than the file or process delivers. Instant download files are complete and under the size limit.
4. **Shop rules:** disclosure block exact and last, How it's made, production partner, no Elf on the Shelf, no private photos.
5. **Mechanics:** title length, 13 tags each 20 or fewer characters (count them), no duplicate tags, no em dashes.
6. **Voice:** plain, specific, warm; reads like Kevin's shop, not a template. Cut filler and stacked adjectives.

Verdict: **Ready for Kevin** (nothing open), **Back to writer** (any Halt; list them), or **Needs Kevin** (only his decisions are left; one-line questions). A draft written before the current rules is checked against today's rules, not the ones it was written under.
